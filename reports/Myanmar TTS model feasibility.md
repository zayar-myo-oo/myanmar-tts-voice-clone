# Evaluate Burmese speech before promising expression

**A modular engine is the realistic starting point:** no candidate reviewed here establishes all requested Burmese voices, expressive controls, licensing freedoms and platform compatibility. MMS supplies a documented Burmese baseline, MyanmarTTS is a compact candidate with permissive license claims, and OmniVoice deserves a separate voice-cloning evaluation. MMS and OmniVoice pretrained weights have noncommercial restrictions. A model's ability to read Burmese does not establish convincing whispering, shouting or acting. This preliminary review was prepared on 17 November 2026; **no candidate was installed, generated speech, or passed listening tests in this research**. Final model selection belongs to Phase 1, followed by measured local inference and pronunciation evaluation in Phase 2.

## Three candidates serve different development needs

| Candidate | Burmese and voices | Direction controls evidenced upstream | Fine-tuning path | Licensing and recommendation |
|---|---|---|---|---|
| MMS `facebook/mms-tts-mya` | Dedicated Burmese checkpoint; one speaker; 16 kHz output | Speaking-rate configuration; no demonstrated emotion or reference cloning API | Separate MMS/VITS fine-tuning implementation exists; Windows build dependencies need review | CC-BY-NC-4.0 weights. Evaluate as a reproducible personal-use baseline |
| `freococo/MyanmarTTS` | Burmese StableTTS; reference-audio conditioning; publisher claims cloning | `length_scale`, sampling parameters and reference audio; no named emotion API found | Matching checkpoint recipe and 8 GB training feasibility remain unverified | Publisher identifies weights as CC0 and code/vocoder as MIT. Evaluate as a small permissive candidate, subject to provenance review |
| `k2-fsa/OmniVoice` | Burmese explicitly listed; reference voice cloning and voice design | Speed/duration and descriptive attributes; Burmese expressive reliability unverified | Full and LoRA training examples available | Apache-2.0 code, **CC-BY-NC pretrained weights**. Evaluate cloning separately |
| Coqui XTTS-v2 | Burmese absent from published supported-language list | Other-language cloning is not evidence of Burmese capability | Fine-tuning exists, but new-language adaptation changes scope | Coqui Public Model License. Exclude from the initial Burmese baseline |

MMS's configuration confirms a single speaker with no speaker embedding, so it cannot directly provide the four proposed voice identities. Its documented Transformers interface makes it a useful baseline for separating application errors from more complex cloning behavior. The checkpoint and its license must remain distinct from the application's source-code license. ([MMS model card](https://huggingface.co/facebook/mms-tts-mya), [checkpoint configuration](https://huggingface.co/facebook/mms-tts-mya/resolve/main/config.json))

MyanmarTTS's publisher reports approximately **31 million parameters and 63 MB fp16 acoustic weights**, plus a separate vocoder. That makes it worth evaluating on limited VRAM, but file size does not establish peak runtime memory. Its CC0/MIT notices are encouraging; the aggregate training-data description does not establish permission or speaker consent for every underlying recording. This is a provenance gap to investigate before redistribution, rather than a finding that the license is invalid. ([MyanmarTTS model card](https://huggingface.co/freococo/MyanmarTTS), [NOTICE](https://huggingface.co/freococo/MyanmarTTS/resolve/main/NOTICE))

OmniVoice lists Burmese in its language table and provides broader reference-based functionality. Its **code and weights have different licenses**, which makes a blanket “Apache-2.0 model” description inaccurate. XTTS-v2 offers no corresponding published native Burmese support and would introduce a new-language research project at the wrong stage. ([OmniVoice languages](https://github.com/k2-fsa/OmniVoice/blob/master/docs/languages.md), [OmniVoice model card](https://huggingface.co/k2-fsa/OmniVoice), [XTTS-v2 model card](https://huggingface.co/coqui/XTTS-v2))

## Expressive direction requires its own evidence

MyanmarTTS's inspected API accepts reference audio, length scaling and sampling controls; it does not expose named anger, sadness, whisper or shout controls. OmniVoice offers descriptive voice design, but upstream documentation says that design training used Chinese and English and warns about instability in low-resource languages. References can also dominate conflicting instructions. None of these facts establishes reliable Burmese acting. ([MyanmarTTS inference source](https://huggingface.co/freococo/MyanmarTTS/blob/main/api.py), [OmniVoice README](https://github.com/k2-fsa/OmniVoice), [OmniVoice tips](https://github.com/k2-fsa/OmniVoice/blob/master/docs/tips.md))

The application should therefore preserve desired directions while reporting what each adapter actually applied. Inserted silence can implement explicit pauses. Audio processing can change speed or pitch, but must be labelled as processing; reduced volume must never be reported as whisper synthesis. Begin with sentence-level rendering and evaluate voice continuity before introducing phrase-level regeneration. The proposed four voices remain target profiles until suitable checkpoints or permissioned references pass listening tests.

## An 8 GB GPU supports evaluation, not guarantees

The RTX 3070 Ti is a sensible target for batch-size-one experiments, but this review establishes **no measured VRAM, throughput or training capacity**. Start with short clips on CPU and CUDA and record peak memory, generation time, output duration and audio failures. Windows inference remains untested for all candidates in this review. OmniVoice documents Apple Silicon MPS, whereas MMS/MyanmarTTS MPS and Intel macOS feasibility need separate verification. ([OmniVoice platform instructions](https://github.com/k2-fsa/OmniVoice))

Fine-tuning requires a second resource gate. MMS has a dedicated implementation involving alignment compilation and checkpoint preparation. OmniVoice provides full and LoRA examples; neither proves a selected Burmese workload fits within 8 GB. Measure one short training step first, then adjust clip length, batch size, accumulation and supported precision. A matching MyanmarTTS fine-tuning recipe remains an explicit research gap. ([MMS fine-tuning repository](https://github.com/ylacombe/finetune-hf-vits), [OmniVoice training examples](https://raw.githubusercontent.com/k2-fsa/OmniVoice/master/examples/README.md))

## Model selection should follow a reproducible gate

The preliminary recommendation is to compare MMS with MyanmarTTS for neutral Burmese speech, then evaluate OmniVoice for reference-based voices if its weight license fits the intended use. Phase 1 should pin exact revisions, inspect inference and training dependencies, review licenses and notices, and prepare the evaluation corpus. Phase 2 should use the same Burmese scripts across candidates, including numbers, punctuation, names and mixed-language text, with a native speaker assessing pronunciation and naturalness. Tokenization and romanization must follow each checkpoint's actual configuration. ([Transformers VITS documentation](https://huggingface.co/docs/transformers/model_doc/vits))

The architecture should allow a neutral baseline to remain useful even if an expressive model fails licensing, memory or pronunciation tests. Keep downloaded models separate from application releases, record their individual licenses and revisions, and expose unsupported controls explicitly. This preserves progress toward an offline studio without making its interface dependent on unverified model promises.
